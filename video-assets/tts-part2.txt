Speak in English with a clear, warm, confident educational voice at a steady documentary pace: Chapter three: connecting the platforms. Supabase provides the authentication service and database connection. Google Cloud supplies the OAuth client that lets users continue with Google. Resend provides branded email delivery for confirmation, recovery, and unlock notifications. Secrets remain in protected environment variables instead of frontend code.

The repeatable integration pattern is simple: configure the provider, store credentials securely, define the callback or webhook, and test the complete journey from the live domain. Manus makes the development loop visible. We inspect files, run type checks, build production bundles, test server procedures, correct errors, create checkpoints, and keep the source synchronized with GitHub. Natural-language development accelerates the loop; validation and secure configuration keep the result reliable.

Chapter four: deployment. The source is connected to GitHub, and the main branch is linked to Vercel. Vercel builds the application and aliases the production deployment to promptforge.com.ng. DNS and domain settings are verified separately from the application. After deployment, we test the real routes with a mobile user agent, confirm the Library loads, check the API path, and verify that authentication redirects use the paid domain rather than a stale preview URL.

Chapter five: discovery and content. Public pages receive titles, descriptions, canonical URLs, keywords where appropriate, Open Graph metadata, organization information, and article structured data. PromptForge adds practical guides and Blog content for prompt engineering, WhatsApp business, image prompting, freelancing, sales copy, and AI-assisted operations. Static SEO documents are generated for public routes and individual Blog articles so crawlers can discover useful content directly.

Analytics are added with restraint. Google Analytics records product signals such as Google sign-in completion and prompt actions. Analytics scripts are deferred until browser idle time where measurement requirements allow. The goal is to learn which workflows help users without making the first screen slower.
